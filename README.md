# 文化資料登録室

公開案内ページ: https://bunka-shiryoshitsu.github.io/bunka-shiryoshitsu/

申請・管理機能: Cloudflare Worker `bunka-shiryoshitsu-checksoft-mountain-b5a9`

## 動作確認

Node.js 22 以降で、初回に `npm ci`、その後 `npm test` を実行します。テストはメモリ内の専用データだけを使い、本番の申込・登録・画像を変更しません。

検証対象は、公開画面のスクリプト、管理認証、受付停止、抽選申込、当選設定、画像提出、登録申請、審査、登録番号照会、JPGの登録・本人受取、登録取消です。資料の審査と登録書JPGの作成は管理者が行います。

## 公開

`wrangler.jsonc` の入口は `worker.js` です。既存の KV、Durable Object、管理キーを維持してください。古い `worker-dashboard9.js` を直接指定すると登録番号管理画面が外れます。

公開前にテストと `wrangler deploy --dry-run` を行い、現在の公開バージョンを記録します。公開は `wrangler deploy --keep-vars`、公開後はトップ・申込・受取・管理画面の応答を確認します。

有料プラン、新規有料サービス、追加費用のある操作は、所有者に相談するまで実行しません。秘密鍵や管理キーをリポジトリに保存しないでください。

開発用 `/_dev/` と切替検証用 `/_cutover/` は本番で404になります。古い検証ファイルを公開入口に指定しないでください。
# 追加提出（2026年9月実装）

- HPの「申請状況の確認・追加提出・登録書の受取り」から、AP番号と受取キーで確認します。審査中は週に一度の確認を案内し、メール・相談対応は設けていません。
- 管理画面の申請詳細から、資料ごとに依頼内容と文章／画像の要否を指定します。翌日から30日間、締切日の23:59（日本時間）まで提出できます。初回の申請期限とは独立します。
- 元の申請・画像を上書きせず、追加依頼と提出履歴を既存のRegistrationIssuerのSQLiteストレージに保存します。画像はJPEG/PNG/WebP、1枚3MB、1依頼10枚まで。画像は認証後のみ取得できます。
- 期限切れは自動不承認にせず、管理者が延長または「未提出による手続終了」を選びます。追加提出一覧で提出待ち・期限切れ・提出済みを確認できます。
- 新規の当選期限は申込月の翌々月1日を含む60日間。既に保存された当選情報の期限は変更しません。
- 新しい有料サービス・バインディング・プラン変更はありません。追加ストレージも既存の無料枠を使用します。
- `npm test`で日付境界・認証・画像制限・二重送信・延長・手続終了・審査後の再提出拒否を検証します。

## 追加提出画像の削除

登録決定・登録見送り・未提出による手続終了時に、当該資料の追加提出画像を削除します。依頼文、追加文章、提出日時、画像の提出履歴は保持します。審査中・追加提出待ちの別資料の画像は削除しません。

削除が途中で失敗した場合も、終了済み資料の追加画像は取得できません。既存のDurable Objectの永続アラームで約1分後に再試行し、大きな履歴は分割処理します。以前のバージョンで残った終了済み画像も、申請状況の表示時と既存の日次処理で整理します。対象の終了状態を確認できない場合は画像を残します。新規のバインディングやCron設定の追加はありません。

## 登録番号ごとの管理者用メモ

`/admin/registration-numbers` の自己所有品専用プール、一般申請用の生成台帳・発行済み台帳に、番号ごとのメモ欄を設けています。5000文字以内、改行可。「保存」で保存し、空欄を保存するとメモを消せます。同じ番号は台帳をまたいで同じメモを表示します。

メモの読み取り・保存は管理キーで認証します。番号・発行台帳とは別に、既存のRegistrationIssuerの永続ストレージへ `registration-number-note:<番号>` として保存し、公開照会・登録書・申請者画面には含めません。世代番号によって別画面からの古い更新を拒否し、保存失敗時や未保存の入力は画面に残します。新しいサービス・バインディング・有料プランへの変更はありません。

## 管理画面の共通操作

管理画面の上部に「1 要対応 → 2 抽選管理 → 3 申請・審査 → 4 登録・登録書 → 5 番号・メモ → 6 設定」を常時表示します。どの画面からも移動でき、選択中の画面を色と現在位置で示します。旧 `/admin-winners` は `/admin?view=lottery` に移動します。

要対応画面では追加提出済み・期限切れ・提出待ちを絞り込み、該当するAP番号・資料番号へ直接移動します。件数は表示中の100件以内を対象とし、続きは「次の100件」で確認します。概要の件数からも対象の一覧へ移動できます。受付の開始・停止は「設定」にまとめています。

申請・登録・番号台帳のAP番号と登録番号は関連画面へのリンクです。申請内の資料は切替ボタンで選択します。検索語、絞り込み、一覧の位置、最後の資料は同じタブ内で保持します。番号・メモでは重複する番号を1枚のカードに集約し、生成・発行履歴は展開して確認します。日時は日本時間で表示します。

名称や追加依頼の未保存の文章は、このタブのsessionStorageに下書きとして保持します。画面移動時に保持・破棄・編集継続を選択できます。タブを閉じると下書きは失われるため、必要な変更は保存・掲載してください。選択中のファイルは保持できず、戻った際の再選択が必要です。番号メモの画面移動時は保存・破棄・編集継続を選択し、保存失敗や競合があればその場に留まります。管理キーは既存と同じくタブ内で共有し、URLには含めません。

審査・取消の確認には対象のAP番号・資料番号・名称または登録番号を表示します。狭い画面では一覧を項目名付きのカードに切り替え、入力欄と操作ボタンは16px以上、主なボタンは高さ44px以上にしています。キーボードで移動し、入力欄・画像・リンクの選択位置を確認できます。

## 番号・メモの大量件数対策

番号は50件ずつ表示し、「前の50件」「次の50件」で切り替えます。検索は全件の番号・AP番号・メモを対象とし、未保存のメモもページ移動中は保持します。画面上の入力欄は最大50件だけを作成し、メモの入力・保存時に全件の表示を再計算しません。

メモは100件単位・同時に最大3通信で取得し、取得済み件数と中止ボタンを表示します。通信ごとに15秒、読み込み全体に60秒の待機上限を設け、失敗・中止後は再試行できます。保存の応答が届かない場合も入力を保持し、再試行には既存の世代番号と同一内容の再送処理を使用します。

再発防止の検証には、1万件の全件検索・重複統合・50件ずつの描画、ページ間の下書き保持・保存、読込中止・再試行・通信待機上限を含めています。画面構築の検証ライブラリは開発用で、公開Workerには含めません。
